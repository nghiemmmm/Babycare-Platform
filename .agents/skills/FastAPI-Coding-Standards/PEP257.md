# PEP 257 -- Python Docstring Convention

## I. Introduction

PEP 257 is the official Python standard that defines how to write
**Docstrings** (Documentation Strings).

A docstring is a string literal placed immediately after the declaration
of a:

-   Module
-   Package
-   Class
-   Function
-   Method

Unlike comments (`#`), docstrings become part of the Python object and
are accessible through the `__doc__` attribute.

## II. General Principles

### 1. Document Every Public Object

Every public object should have a docstring.

Includes:

-   Modules
-   Packages
-   Public Classes
-   Public Functions
-   Public Methods
-   FastAPI Endpoints
-   Services
-   CRUD Functions

### 2. Describe What, Not How

Good:

    """Create a new student account."""

Bad:

    """Insert student into PostgreSQL using SQLAlchemy."""

### 3. Keep It Concise

Good:

    """Return the authenticated user."""

### 4. Use English

All project docstrings should be written in English.

### 5. Complement Type Hints

Type hints describe data types.

Docstrings describe behavior.

## III. Module Docstrings

Example:

    """
    Student CRUD operations.

    This module contains database operations related to students.
    """

## IV. Class Docstrings

    class StudentService:
        """Provide business logic for student management."""

## V. Function Docstrings

    def create_student():
        """Create a new student."""

## VI. One-Line Docstrings

Rules:

-   One sentence.
-   Capitalize the first letter.
-   End with a period.
-   Use the imperative mood.

Example:

    """Return all students."""

## VII. Multi-Line Docstrings

    """
    Create a new student.

    Validate the student information before saving it into the database.
    """

## VIII. Google Style Example

    def create_student(student: StudentCreate, db: Session) -> Student:
        """
        Create a new student.

        Validate the student information and save it into the database.

        Args:
            student: Student creation data.
            db: Active database session.

        Returns:
            The newly created student.

        Raises:
            HTTPException: If the username already exists.
        """

## IX. FastAPI Examples

Router:

    @router.get("/")
    async def get_students():
        """Return all students."""

Service:

    class StudentService:
        """Handle student business logic."""

CRUD:

    def get_student_by_id():
        """Retrieve a student by ID."""

Schema:

    class StudentCreate(BaseModel):
        """Schema used to create a student."""

## X. Project Standards

-   Every .py file has a module docstring.
-   Every public class has a class docstring.
-   Every public function has a function docstring.
-   Every public method has a method docstring.
-   Every FastAPI endpoint has a docstring.
-   Every service has a docstring.
-   Every CRUD function has a docstring.
-   Always use triple double quotes.
-   Use the imperative mood.
-   End the summary with a period.
-   Write all docstrings in English.
-   Do not repeat type hints.

## XI. Code Review Checklist

-   Module docstring exists.
-   Public class docstring exists.
-   Public function docstring exists.
-   Public method docstring exists.
-   Endpoint docstring exists.
-   Service docstring exists.
-   CRUD docstring exists.
-   Written in English.
-   Uses Google Style where appropriate.
