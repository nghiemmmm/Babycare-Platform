# BabyCare AI Database Documentation (Firebase Firestore NoSQL)

## Overview

This document describes the production database schema for BabyCare AI, designed specifically for **Google Cloud Firestore (NoSQL Document Database)**.

To optimize performance and minimize read/write costs on Firestore, the design avoids relational concepts like SQL `JOIN`s, foreign keys, and many-to-many intermediate tables. Instead, it utilizes **nested arrays, sub-collections, and document-level embedding**.

---

## Collections & Documents Schema

### 1. User & Authentication Module

#### `users` (Root Collection)
Stores parent user accounts and profile configurations.
- **Document ID**: `user_id` (Generated by Firebase Authentication or UUID)
- **Fields**:
  - `username` (string, unique)
  - `email` (string, unique)
  - `password_hash` (string)
  - `phone` (string, optional)
  - `role` (string: "ADMIN", "USER", "STAFF")
  - `active` (boolean)
  - `first_login` (boolean)
  - `created_at` (timestamp)
  - `updated_at` (timestamp)
  - `last_login_at` (timestamp)

#### `users/{user_id}/login_logs` (Sub-collection)
Stores user login history for security audits.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `ip_address` (string)
  - `user_agent` (string)
  - `logged_at` (timestamp)

---

### 2. Baby Profile & Growth Module

#### `babies` (Root Collection)
Stores baby profiles and manages guardian permissions.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `name` (string)
  - `birth_date` (string/timestamp)
  - `gender` (string: "boy", "girl", "unknown")
  - `guardians` (array of strings): List of `user_id`s who have permission to access/manage this baby's profile. Used for access control check: `guardians array_contains user_id`.
  - `created_at` (timestamp)
  - `updated_at` (timestamp)

#### `babies/{baby_id}/growth_logs` (Sub-collection)
Tracks the baby's physical development.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `height` (number, cm)
  - `weight` (number, kg)
  - `head_circumference` (number, cm, optional)
  - `logged_at` (timestamp)

---

### 3. Vaccination Module

#### `vaccines` (Root Collection)
A master catalog of available vaccines (Read-only reference data).
- **Document ID**: `vaccine_code` (e.g., "BCG", "HepB")
- **Fields**:
  - `name` (string)
  - `disease` (string)
  - `recommended_age_months` (number)
  - `manufacturer` (string, optional)
  - `description` (string, optional)

#### `babies/{baby_id}/vaccinations` (Sub-collection)
Tracks the specific vaccine schedule and history for each baby.
- **Document ID**: Auto-generated by Firestore (or matches `vaccine_code`)
- **Fields**:
  - `vaccine_code` (string): Reference to the vaccine catalog
  - `vaccine_name` (string): Denormalized for fast reads
  - `scheduled_date` (timestamp)
  - `administered_date` (timestamp, optional)
  - `status` (string: "scheduled", "completed", "overdue")
  - `notes` (string, optional)

---

### 4. Healthcare, Alerts & Notifications

#### `healthcare_tips` (Root Collection)
Education articles for parents.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `title` (string)
  - `content` (string)
  - `category` (string)
  - `min_age_months` (number)
  - `max_age_months` (number)
  - `created_at` (timestamp)

#### `alert_rules` (Root Collection or Static Config)
Rules used by the personalization engine to trigger health alerts.
- **Document ID**: `rule_code`
- **Fields**:
  - `name` (string)
  - `condition` (string)
  - `severity` (string: "low", "medium", "high")

#### `users/{user_id}/notifications` (Sub-collection)
Stores notification and alert history for each parent.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `baby_id` (string, optional)
  - `title` (string)
  - `message` (string)
  - `type` (string: "vaccine", "health_alert", "tip")
  - `read` (boolean)
  - `created_at` (timestamp)

---

### 5. AI Chatbot & Knowledge Base (GraphRAG)

#### `chat_threads` (Root Collection)
Conversation threads between parents and the AI chatbot.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `user_id` (string)
  - `baby_id` (string, optional): For personalizing the AI responses
  - `title` (string)
  - `created_at` (timestamp)
  - `updated_at` (timestamp)

#### `chat_threads/{thread_id}/messages` (Sub-collection)
Individual messages within a conversation thread.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `sender` (string: "user", "assistant")
  - `content` (string)
  - `created_at` (timestamp)
  - `sources` (array of maps): Denormalized list of citations from the GraphRAG indexing:
    - `document_id` (string)
    - `title` (string)
    - `snippet` (string)

#### `knowledge_documents` (Root Collection)
Metadata for medical documents indexed in the GraphRAG system.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `title` (string)
  - `category` (string)
  - `url` (string, optional)
  - `last_indexed` (timestamp)

---

### 6. Nutrition Recommendation Module

#### `babies/{baby_id}/nutrition_recommendations` (Sub-collection)
AI-generated personalized nutrition and feeding guides.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `title` (string)
  - `age_months` (number)
  - `daily_schedule` (array of maps)
  - `allowed_foods` (array of strings)
  - `forbidden_foods` (array of strings)
  - `generated_at` (timestamp)

---

### 7. Health Records Module

#### `babies/{baby_id}/health_records` (Sub-collection)
Tracks symptoms, doctor visits, and illness records.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `symptoms` (array of strings)
  - `diagnosis` (string, optional)
  - `treatment` (string, optional)
  - `doctor_name` (string, optional)
  - `notes` (string, optional)
  - `recorded_at` (timestamp)

---

### 8. Calendar & Google Synchronization

#### `babies/{baby_id}/calendar_events` (Sub-collection)
Events synchronized with Google Calendar (e.g. vaccination appointment).
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `google_event_id` (string, unique)
  - `title` (string)
  - `description` (string)
  - `start_time` (timestamp)
  - `end_time` (timestamp)
  - `synced_at` (timestamp)

## Architecture Summary (Hierarchy)

```text
/users (Collection)
  ├── {user_id} (Doc) ── /login_logs (Sub-col)
  └── /notifications (Sub-col)

/babies (Collection)
  ├── {baby_id} (Doc)
        ├── guardians: [user_id_1, user_id_2]
        ├── /growth_logs (Sub-col)
        ├── /vaccinations (Sub-col)
        ├── /health_records (Sub-col)
        └── /calendar_events (Sub-col)

/vaccines (Collection)
  └── {vaccine_code} (Doc)

/healthcare_tips (Collection)
/alert_rules (Collection)
/knowledge_documents (Collection)

/chat_threads (Collection)
  ├── {thread_id} (Doc) ── /messages (Sub-col)
```

## Technologies & Firestore Best Practices

1. **Denormalization**: Selected fields (e.g., vaccine name) are denormalized inside the sub-collection records to avoid secondary read queries.
2. **Sub-collections**: Used for relational child data to keep root collections clean and query performance constant as the database grows.
3. **NoSQL Access Control**: Security rules can check permissions on the `/babies` collection directly using:
   `resource.data.guardians.hasAny([request.auth.uid])`
